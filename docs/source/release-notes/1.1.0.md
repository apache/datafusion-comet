# Comet 1.1.0 Release Notes

Comet 1.1.0 fixes about 90 bugs that shipped in 1.0.0, about 40 of which returned results that
differed from Spark. Before upgrading, read the
[upgrade guide](../user-guide/latest/migration-guide.md#upgrading-to-comet-110) for the behavior
changes in this release, and the known regressions below.

## Known Regressions

After the first release candidate was cut, an audit of every pull request in 1.1.0 against 1.0.0
found the regressions below ([#6399](https://github.com/apache/datafusion-comet/issues/6399)). Each
one is a case that 1.0.0 handled correctly and 1.1.0 doesn't. Each entry names a setting that avoids
the problem, and each setting has been checked against the regression's reproducer on 1.1.0. The
settings make the affected expression or operator fall back to Spark, so queries that use it can run
more slowly. Fixes are planned for 1.1.1, and
[#6402](https://github.com/apache/datafusion-comet/issues/6402) has the current list.

### Wrong Results

- **`regr_slope`, `regr_intercept`, `regr_r2`, `regr_sxx`, `regr_syy` and `regr_sxy`**
  ([#6423](https://github.com/apache/datafusion-comet/issues/6423)). When a group's variable is
  constant at a value that binary floating point can't represent exactly, such as 0.1, and the
  group's rows are aggregated in more than one partition, these return large values or a spurious
  `regr_r2` instead of NULL, and `regr_sxx` returns a tiny number instead of 0.0. To avoid it, set
  all five of these to `false`: `spark.comet.expression.RegrSlope.enabled`,
  `spark.comet.expression.RegrIntercept.enabled`, `spark.comet.expression.RegrR2.enabled`,
  `spark.comet.expression.RegrSXY.enabled` and `spark.comet.expression.RegrReplacement.enabled`.
  `regr_sxx` and `regr_syy` are covered by the last one. An aggregate that uses any of these
  functions then runs in Spark as a whole.
- **Decimal results from DSv2 catalog functions**
  ([#6425](https://github.com/apache/datafusion-comet/issues/6425)). A function from a DSv2
  function catalog that returns a decimal whose scale differs from its declared result type returns
  a value that is off by a power of ten, such as 0.03 instead of 3.00. Functions that only implement
  `produceResult` aren't affected. To avoid it, set `spark.comet.expression.Invoke.enabled=false`
  for a function whose `invoke` method is an instance method, or
  `spark.comet.expression.StaticInvoke.enabled=false` for a static one. Set both if you aren't sure.
  `StaticInvoke` also covers built-in functions such as `base64`, `url_encode` and `luhn_check`,
  which then run in Spark.
- **Iceberg's `years`, `months`, `days` and `hours` before 1970**
  ([#6426](https://github.com/apache/datafusion-comet/issues/6426)). For a timestamp before 1970
  whose microseconds are 999999 at a unit boundary, such as `1969-01-01 00:00:00.999999`, these
  return one unit more than Iceberg does, and a filter on them can miss rows. To avoid it, set
  `spark.comet.expression.StaticInvoke.enabled=false`. If you use Iceberg's SQL extensions, also set
  `spark.comet.expression.ApplyFunctionExpression.enabled=false`. These settings also run Iceberg's
  `bucket` and `truncate` functions in Spark, along with the built-in functions that `StaticInvoke`
  covers.
- **`RANK` and `DENSE_RANK` over a nested floating-point sort key**
  ([#5507](https://github.com/apache/datafusion-comet/issues/5507)). On Spark 3.5 and later, a
  `RANK()` or `DENSE_RANK()` filtered to its top rows, as in `WHERE rnk <= 1`, drops rows that tie
  in Spark when the `ORDER BY` key is an array or struct holding `-0.0` and `0.0`, or two NaN
  representations. To avoid it, set `spark.comet.exec.windowGroupLimit.enabled=false`, which runs
  the limit and the window above it in Spark for every such top-k query.

### Errors

- **`IF` with a map or struct literal branch**
  ([#6334](https://github.com/apache/datafusion-comet/issues/6334)). `IF(c, m, map('z', 0))` over a
  map or struct column fails with `column types must match schema types` on a batch where every row
  takes the same branch. To avoid it, write the expression with `CASE WHEN` instead of `IF`, which
  runs natively and returns the right result. Setting `spark.comet.expression.If.enabled=false` also
  works, but it sends much more to Spark, because Comet also plans `nvl2`, `nullif`, `count_if`,
  `ln` and, with ANSI mode off, division with `IF`.
- **Iceberg reads of a column that gained a nested field**
  ([#6504](https://github.com/apache/datafusion-comet/issues/6504)). On an Iceberg table where a
  struct column, or the struct inside an array or map, gained a field after some data files were
  written, the native Iceberg scan fails with `Incorrect number of arrays for StructArray fields`
  when it reads one of the older files. Plain reads of such a column already failed in 1.0.0. In
  1.1.0, `IS NULL` and `IS NOT NULL` filters on the column, non-outer `explode` of such an array,
  and joins on such a struct fail too, where 1.0.0 ran them in Spark. To avoid it, set
  `spark.comet.scan.icebergNative.enabled=false`, which reads every Iceberg table with Spark's
  reader.

### Performance

- **More rows shuffled by adaptive partial aggregation**
  ([#6466](https://github.com/apache/datafusion-comet/issues/6466)). Comet 1.1.0 lets a partial
  aggregate that only groups, or only counts one column, stop aggregating once the first 100,000
  rows of a task are more than 80% distinct, and send the rest of the task's rows to the shuffle as
  they are. A task whose keys repeat after a mostly distinct start can then shuffle several times
  more rows than in 1.0.0. The results are correct. To restore the 1.0.0 behavior, set
  `spark.comet.exec.respectDataFusionConfigs=true` and
  `spark.comet.datafusion.execution.skip_partial_aggregation_probe_ratio_threshold=1.1`, as the
  [tuning guide](../user-guide/latest/tuning/operators.md#adaptive-partial-aggregation) describes.
  The first setting is meant for testing, and it also passes every other `spark.comet.datafusion.*`
  setting through to DataFusion.
- **Partial aggregates without the Comet shuffle manager.** When the final aggregate runs in Spark,
  which happens for every aggregate if the Comet shuffle manager isn't installed, the partial `avg`,
  decimal `sum`, `stddev`, `variance`, `corr`, `first`, `last` and a few others now run in Spark
  too. In 1.0.0 they ran natively, and `avg` could return NULL in this plan
  ([#5419](https://github.com/apache/datafusion-comet/issues/5419)). Installing the Comet shuffle
  manager keeps them native.
